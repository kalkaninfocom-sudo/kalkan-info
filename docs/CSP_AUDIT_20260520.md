# CSP `unsafe-inline` Audit Raporu

**Tarih:** 2026-05-20
**Kapsam:** Tüm HTML (`*.html`, `admin/*.html`, `antik-kentler/*.html`, `p/*.html`) + JS modülleri (`js/*.js`)
**Amaç:** Faz 4.I'da CSP'den `'unsafe-inline'` çıkarmak için inline script + `innerHTML` envanterini çıkar.

| Kapsam | Bulgu |

## XSS Risk Önceliklendirme

### ✅ Güvenli (sanitize edilmiş veya statik)

- `js/concierge-ai-modal.js:460` — `aiBubble.innerHTML = linkify(aiText)`
  - `linkify()` önce `escapeHTML(text)` çağırıyor, sonra link pattern'leri ekliyor → **güvenli**.
- `js/concierge-ai-modal.js:183`, `:359` — statik HTML template + üç dot animasyonu.
- `js/concierge-modal.js:217`, `:433` — statik HTML template.
- `tatil-asistani.html:1024` — `container.innerHTML = ''` — sadece temizlik.
- `villalar.html:358,362` — `KalkanData.villaCard()` çıktısı; `data/villalar.json` build-time controlled.
- `admin.html:183` — auth guard banner, statik.
- `admin/jobs.html:266,311,330,339` — admin panel, auth gerekli (Faz 4.H gatekeeper eklendikten sonra ileri risk yok).
- `ilan-ver.html:420,513,558` — SVG ikon + `KalkanData.renderJobCard(job)`; form data Supabase RLS arkasında.
- `hizmet-ekle.html:218` — `user.photoURL` Supabase Auth (Google OAuth) → kontrollü URL.
- `js/lost-found.js:158-376` — `_itemCard()` user içerik render; **doğrula**: user input alanları (title, description, contact) sanitize ediliyor mu?

### ⚠️ Doğrulanmalı (potansiyel risk)

1. **`js/lost-found.js` `_itemCard()` user girdisi** — kullanıcının ilan başlığı/açıklaması XSS payload olabilir. `escapeHTML` çağrısı var mı kontrol et.
2. **`js/news.js:6`** — RSS'ten gelen başlık/özet `innerHTML`'e basıyorsa kaynak kontrolü gerek (3rd party RSS).
3. **`js/reviews.js:7`** — Faz 3.C ile gelen review'ler user-generated; mutlaka `escapeHTML` zorunlu.

### 🔴 Refactor Gerekli (Faz 4.I)

Tüm HTML'lerdeki page-bootstrap inline `<script>` block'ları (her sayfada ~5-15 satır) → `js/inline/{slug}.js`'e taşı, CSP'den `unsafe-inline` çıkar. ~30 sayfa × ortalama 2 block = ~60 inline block tasınacak.

Alternatif: CSP nonce mekanizması (server-side per-request) — Vercel Edge Middleware ile mümkün ama maintenance yükü daha yüksek. External JS'e taşımak daha temiz.

## Eylem Planı (Faz 4.I'da yürütülecek)

1. `js/lost-found.js` + `js/news.js` + (gelecek) `js/reviews.js` için kullanıcı içerikli alanlarda `escapeHTML` zorunlu kıl.
2. Tüm HTML'lerdeki inline `<script>` block'ları batch script ile `js/inline/{slug}.js`'e taşı.
3. `vercel.json` CSP'den `'unsafe-inline'` çıkar (sadece script-src; style-src'de Tailwind CDN için kalabilir veya `unsafe-hashes` + nonce).
4. Lighthouse + manual smoke test 20 sayfada.

## Notlar

- CSP `style-src 'unsafe-inline'` ayrı bir konu — Tailwind CDN + inline `<style>` blokları çok yaygın, kaldırması büyük iş. Şimdilik sadece `script-src` hedef.
- AI Concierge'in `linkify()`'i örnek alınabilir doğru pattern (escape önce, sonra controlled HTML inject).
